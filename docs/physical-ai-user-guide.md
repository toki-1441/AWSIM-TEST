# Physical AI 利用マニュアル

このマニュアルは、小型車シミュレータを初めて使う方向けです。まず手動で走らせ、次にカメラ画像・走行操作・アノテーションを保存し、必要に応じて強化学習を試します。プログラムを編集する必要はありません。

対象はこのプロジェクトの **Linux 版 Physical AI** です。上流 AWSIM の市街地デモとは別の機能です。実装の詳細・検証記録は [Operator Workflows](physical-ai-operator-workflows.md) を参照してください。

## 1. 起動する

端末を開き、`Assets`、`scripts`、`Build` が入っている `AWSIM-TEST` フォルダへ移動してください。以下のコマンドは、すべてそのフォルダで実行します。コマンドの先頭に `$` を追加する必要はありません。

```bash
./Build/AWSIM.x86_64
```

「Physical AI — choose how to start」という画面が表示されたら準備完了です。画面を表示できるデスクトップ環境と、Unity HDRP を実行できる GPU・ドライバーが必要です。

実行ファイルがない場合は、Unity Editor を閉じてからビルドします。Unity のバージョンは `ProjectSettings/ProjectVersion.txt` の指定に合わせてください。

```bash
scripts/build_linux.sh --clean
```

ビルド後、上の起動コマンドを実行します。`--clean` はプレイヤーを作り直しますが、記録済みデータセットを削除しません。Unity が標準の Hub インストール先にない場合は、環境変数 `UNITY_BIN` に Editor の実行ファイルの絶対パスを指定します。詳細はリポジトリの `SKILLS.md` を参照してください。

## 2. まず手動で走る

1. 起動画面で **Manual driving** を選びます。
2. `Scenario` は `nominal`、`Map` は `endless`、`Vehicle` は `assisted` にします。
3. まず記録せず試す場合は `Record on start` をオフにします。
4. `Start` を押し、走行画面の背景をクリックします。
5. `W` を短く押して発進し、`A`・`D` で曲がります。

| 操作 | キー／ボタン | 意味 |
| --- | --- | --- |
| 加速 | W または ↑ | 押している間、加速 |
| ブレーキ | S または ↓ | 減速する。後退操作ではない |
| 左右に曲がる | A・D または ←・→ | 左右の操舵 |
| やり直す | R / Restart (R) | 同じエピソードの開始位置へ戻す |
| 一時停止／再開 | Pause / Resume | シミュレーションを止める／再開する |
| 記録開始／停止 | F8 / Start recording / Stop recording | 走行データの保存を切り替える |

`assisted` はスリップを抑えた操作しやすいモードです。`dynamic` はタイヤの滑りを含むモデルです。最初の操作練習や収集は `assisted` で構いません。ただし、そのデータは実車の物理特性を証明するものではありません。

右側の小窓で車載カメラの画像を確認できます。エピソード終了が表示されたら `R` でやり直してください。終了するときは記録を止め、ウィンドウを閉じます。

**文字入力欄を選んでいる間は、誤操作防止のため走行キーが無効になります。** 入力後は走行画面の背景をクリックしてください。

## 3. 走行データとアノテーションを記録する

### 収集前の設定

起動画面の Manual driving で、次の項目を選びます。

| 画面の項目 | 初回の設定例 | 保存されるもの |
| --- | --- | --- |
| Dataset output directory | `Build/datasets` | 記録先の親フォルダ |
| Record RGB camera | オン | 普通のカラー画像 |
| Metric camera depth + validity mask | オン | 奥行きと、有効な画素を示すマスク |
| BEV ground truth + object annotations | オン | 真上から見たクラス別地図と物体情報 |
| Image width / Image height | 160 / 90 | カメラ画像の横・縦の画素数 |
| Capture Hz | 5 | シミュレーション時間 1 秒あたりの画像取得頻度 |
| Record on start | オフ | F8 で記録を始める |

これは軽めの確認用設定です。必要に応じて解像度や頻度を上げてください。画像の頻度と、物理ステップごとの走行記録の件数は一致しません。

### 最初の 1 本を保存する

1. `Start` で走行画面へ進みます。
2. `F8` を押します。画面の表示が `RECORDING` になり、`records` が増えることを確認します。
3. 10〜30 秒ほど走ります。
4. 注釈を残したい場面で、タグ入力欄に `左カーブ` などと入力し、`Add event tag` を押します。
5. 走行画面をクリックして操作へ戻ります。
6. `F8` または `Stop recording` で止め、画面に表示された保存先を控えます。

タグは「ボタンを押した時点のイベント」です。画像を囲む手描きの矩形アノテーションではありません。物体の自動アノテーションは BEV の設定で別途保存されます。

保存先には `teleop-日時-識別子` という新しいフォルダができます。記録を再開すると別のフォルダになります。記録中に `R` でやり直す場合も記録が分割されるため、直前と直後のフォルダを確認してください。

| ファイル／フォルダ | 内容 |
| --- | --- |
| `manifest.json` | 設定、車両モデル、カメラの取り付け位置・画角など |
| `frames.jsonl` | 各ステップの操作・車両状態・画像情報など |
| `events.jsonl` | 入力したタグ、コース更新などのイベント |
| `sensors/` | 有効にした深度・BEV・物体アノテーションなど |

JSON は設定などを文字で表す形式、JSONL は 1 行ごとに 1 件の JSON を並べた形式です。通常は直接読むより、次のレビュー画面を使ってください。移動・バックアップ時は **記録フォルダ全体** をコピーします。

## 4. 記録をブラウザで確認する

Python 3 が必要です。この確認ツールには追加の Python パッケージは不要です。記録を止めてから実行します。

次の `teleop-実際のフォルダ名` を、先ほど控えた名前に置き換えてください。

```bash
python3 scripts/review_recording.py "Build/datasets/teleop-実際のフォルダ名" --output Build/reviews/first-drive
```

`Build/reviews/first-drive/review.html` をファイルマネージャーからブラウザで開きます。再生・一時停止、スライダー移動、RGB／深度／BEV の比較、タグ位置への移動ができます。深度画像にマウスを重ねると値を確認できます。

同じ出力先がすでに空でない場合、上書き防止で失敗します。次は `Build/reviews/second-drive` のように新しい名前にしてください。

併せて作られる `report.json` はデータの構造・整合性の検査結果です。「運転が上手い」「実車に適用できる」という評価ではありません。このレビューは記録の閲覧であり、Unity 上で車両を再走行させる機能ではありません。

### 深度と BEV の読み方

- 深度はカメラの光軸方向の距離で、単位はメートルです。空や測定範囲外などの無効画素は 0 と有効性マスクで区別します。PNG は見やすく変換したプレビューであり、測定値は `.depth.f32` にあります。
- BEV は車両の周囲を真上から見た正解データです。画像上側が車両の前方です。標準の 128 画素 × 0.1 m/画素なら、一辺 12.8 m の範囲です。
- BEV のクラス番号は、0: 背景、1: 道路、2: 境界、3: 障害物、4: 他車、5: 自車です。
- BEV や物体情報はシミュレータが知っている正解です。カメラ画像だけで推定できた結果ではありません。

## 5. 無限マップと固定マップを使い分ける

`Map` の意味は次のとおりです。

| 設定 | 動作 | 用途 |
| --- | --- | --- |
| endless | 進行に合わせて先の道路を生成し、過去の道路を整理する | 長い走行・多様なデータ収集 |
| fixed、Map file は空欄 | Seed から有限の閉じたコースを生成する | 同じ条件での繰り返し |
| fixed、Map file を指定 | 保存済みの道路形状を読み込む | 特定の道路を共有・再利用 |

Seed は生成に使う番号です。同じ設定・同じ実装で条件を揃えるために使います。

道路を保存するには、手動走行画面の保存先欄に `Build/maps/my-course.json` などの未使用の名前を入力し、`Save map (new file)` を押します。次回の起動で `Map` を `fixed` にして、`Map file` にそのパスを指定します。

無限マップから保存されるのは、**その時点で保持されている道路形状**です。読み込み後は有限の固定マップであり、無限生成の続きにはなりません。車両の保存時の位置・速度も復元しません。既存ファイルへの上書きはできないので、新しい名前を使ってください。

## 6. カメラ位置と起動設定を保存する

カメラの取り付け位置・角度は固定設定です。エピソードや Seed によってランダムには変わりません。

| 画面の項目 | 初期値 | 意味 |
| --- | --- | --- |
| Height above ground | 0.15 | 地面からの高さ 15 cm |
| Forward offset | 0.077 | 車両原点から前へ 7.7 cm |
| Right offset | 0 | 左右のずれなし |
| Pitch | 22 | 下向きに 22 度 |
| Yaw / Roll | 0 / 0 | 左右の向き／傾き |

距離はメートル、角度は度です。たとえば高さ 20 cm は `0.20` と入力します。小数点には `.` を使ってください。

### 画面から保存・読み込み

起動画面上部の設定ファイル欄に `Build/config/my-manual.json` などを指定し、設定後に `Save config (replace)` を押します。**このボタンは既存の設定ファイルを上書きします。** 次回は同じパスを指定して `Load config` を押します。

設定ファイルを使って直接起動することもできます。この場合、選択画面をスキップします。

```bash
./Build/AWSIM.x86_64 -physicalAiConfig Build/config/my-manual.json
```

### コピーして使える設定例

テキストエディタで次の内容を `Build/config/my-manual.json` に保存しても構いません。親フォルダがない場合は作成してください。JSON 内にはコメントを書かず、最後の項目の後ろにカンマを付けません。

```json
{
  "schemaVersion": 1,
  "mode": "manual",
  "scenario": "nominal",
  "mapMode": "endless",
  "seed": 1,
  "vehicleModel": "assisted",
  "outputDirectory": "Build/datasets",
  "recordOnStart": false,
  "rgb": true,
  "depth": true,
  "bev": true,
  "imageWidth": 160,
  "imageHeight": 90,
  "captureHz": 5,
  "cameraHeightMeters": 0.15,
  "cameraForwardMeters": 0.077,
  "cameraLateralMeters": 0,
  "cameraPitchDegrees": 22,
  "cameraYawDegrees": 0,
  "cameraRollDegrees": 0
}
```

省略した項目には既定値が使われます。パスは設定ファイルの置き場所ではなく、**起動コマンドを実行したフォルダからの相対パス**です。迷ったら絶対パスを指定してください。

コマンド末尾で指定したオプションは設定ファイルより優先されます。例として、Seed だけを変える場合は次のようにします。

```bash
./Build/AWSIM.x86_64 -physicalAiConfig Build/config/my-manual.json -physicalAiSeed 42
```

## 7. 強化学習を開始・停止・再開する

強化学習（RL）は、シミュレータで試行を繰り返し、報酬を使って方策を更新する機能です。ここでは学習処理の動作確認から始めます。短時間の実行で良い運転が身に付くことを保証するものではありません。

### Python の準備

`torch`、`numpy`、`Pillow` が入った Python 環境が必要です。既存の学習用環境があれば、それを使ってください。新しく作る場合の一例です。パッケージ取得にはネット接続とディスク容量が必要です。

```bash
python3 -m venv Build/venv-rl
Build/venv-rl/bin/python -m pip install torch numpy Pillow
Build/venv-rl/bin/python -c "import torch, numpy, PIL; print('RL dependencies OK')"
```

これは環境準備の例で、依存バージョンを固定した再現環境ではありません。環境作成に失敗する場合は、Linux 環境の管理者に Python の venv 対応を確認してください。

### 最初の短い実行

1. 起動画面で `RL rollout` を選びます。
2. 最初は `nominal`、`assisted`、`Trainer device` は `cpu` にします。RGB は有効にします。
3. `Manage the Python trainer from this player` をオンにします。
4. `Python executable` に `Build/venv-rl/bin/python`（または既存環境の Python パス）を入力します。
5. `Trainer script` は `scripts/train_vision_rl.py`、出力先は `Build/rl` とします。
6. `Episodes` は 2、`Seconds per episode` は 20 など、小さい値で試します。
7. `Resume checkpoint` は空欄にします。`Start training when the scene opens` をオンにして `Start` を押します。

Python の起動・接続待ちの間はシミュレーションが停止します。学習が始まったら、画面の状態表示と出力先を確認します。これは単一環境の基本的な学習例であり、高性能な学習済みドライバーではありません。

### 停止と再開

途中で止める場合は **Stop and save** を押し、`Checkpoint saved` の表示を確認してから終了してください。強制終了では最新状態が残らない場合があります。

各実行は `Build/rl/rl-日時-識別子/` に保存されます。

| ファイル | 内容 |
| --- | --- |
| `checkpoint.pt` | 学習再開用の状態 |
| `metrics.jsonl` | エピソードごとの学習指標 |
| `trainer.log` | Python のログ・エラー |
| `launch.json` / `environment.json` | 起動設定・学習環境の契約 |

再開するには、同じ環境設定を読み込み、`Resume checkpoint` に保存済み `checkpoint.pt` のパスを指定して開始します。走行画面の `Resume training` からも再開できます。再開先は新しい実行フォルダになるため、元の記録は上書きしません。

カメラ位置・解像度・マップ・車両モデルなどが異なると、互換性チェックで再開を拒否します。その場合は元の設定に戻すか、新規学習にしてください。車両の途中の位置から再開するのではなく、エピソード境界の学習状態を復元します。

現在の方策入力は RGB と計画用ベクトル、出力は速度・横位置の目標です。深度・BEV を保存しても、自動的に方策入力にはなりません。また、手動走行の操作記録はアクセル・ブレーキ・操舵であり、そのまま計画方策の模倣学習用の正解にできるわけではありません。

## 8. 困ったとき

| 症状 | 確認すること |
| --- | --- |
| 起動コマンドでファイルがないと言われる | `AWSIM-TEST` フォルダで実行しているか、ビルドが完了したか確認 |
| ビルドがプロジェクトを開けない | 同じプロジェクトの Unity Editor を閉じる |
| 起動時の選択画面が出ない | `-physicalAi…` オプションなしで起動し直す |
| W・A・S・D が効かない | 入力欄からフォーカスを外す。Pause 中やエピソード終了でないか確認 |
| スリップが強い | Vehicle を `assisted` にする。記録にはモデルの違いが残る |
| カメラが車体に近すぎる | Height above ground と Forward offset を確認。変更後は新しい記録で小窓を確認 |
| 深度・BEV が出ない | 起動前に対応するチェックをオンにしたか確認 |
| 記録件数が増えない | RECORDING 表示、Pause、エピソード終了、保存先の書込権限・空き容量を確認 |
| 設定・マップを読み込めない | 起動場所から見たパスと JSON の書式を確認。エラー表示も読む |
| 保存やレビューの出力先が拒否される | マップとレビューは未使用の名前を選ぶ。設定の replace は上書きなので注意 |
| 動作が重い／記録が大きい | 解像度や Capture Hz を下げる。不要な深度・BEV をオフにし、短い記録に分ける |
| レビューでメモリが足りない | 長大な記録の読み込みはメモリを使う。収集時から短い区間に分ける |
| RL が接続待ち／エラーになる | Python パス・依存パッケージ・trainer.log を確認。同じポート 5015 を別の実行が使っていないか確認 |
| RL が再開を拒否する | 保存時のカメラ・マップ・車両などの設定に戻す。別条件なら新規学習にする |

解決しない場合は、起動コマンド、設定ファイル、画面のエラー、再現手順を控えてください。プレイヤーログの場所を明示して起動すると調査しやすくなります。保存先フォルダは先に作っておきます。

```bash
mkdir -p Build/logs
./Build/AWSIM.x86_64 -logFile Build/logs/manual-player.log
```
